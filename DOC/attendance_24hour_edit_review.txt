2. DATABASE ARCHITECTURE & SCHEMA CHANGES
================================================================================

1. Dedicated Immutable Audit History Table:
   Table: public.attendance_audit_history
   Columns:
   - id: UUID PRIMARY KEY DEFAULT gen_random_uuid()
   - attendance_id: UUID NOT NULL REFERENCES public.attendance(id) ON DELETE CASCADE
   - student_id: UUID NOT NULL REFERENCES public.students(id) ON DELETE CASCADE
   - previous_status: VARCHAR(20) NOT NULL
   - new_status: VARCHAR(20) NOT NULL
   - original_marked_by: UUID NOT NULL REFERENCES public.profiles(id)
   - edited_by: UUID NOT NULL REFERENCES public.profiles(id)
   - original_created_at: TIMESTAMPTZ NOT NULL
   - edited_at: TIMESTAMPTZ NOT NULL DEFAULT NOW()
   - reason: TEXT NOT NULL
   - is_super_admin_override: BOOLEAN NOT NULL DEFAULT FALSE

2. Attendance Table Enhancements:
   Table: public.attendance
   Added Columns:
   - last_edited_by: UUID REFERENCES public.profiles(id)
   - edit_reason: TEXT

3. Row Level Security (RLS) Policies:
   - public.attendance_audit_history:
     * Read policy: Admins, Secretaries, and Staff Mentors can read audit histories.
     * Insert policy: Authenticated Staff Mentors and Admins can insert audit rows.
   - public.attendance:
     * UPDATE policy: Enabled for Admins without restrictions, and for Staff Mentors
       where `mentor_id = auth.uid()` AND `NOW() < created_at + INTERVAL '24 hours'`.
   - public.profiles:
     * RLS policy updated to allow Staff Mentors to read student profiles for Abdul Kalam
       attendance rosters without encountering 0-row RLS locks.

3. API ARCHITECTURE & ENDPOINTS
================================================================================

1. PATCH /api/attendance/abdul-kalam
   Dynamic alias: PATCH /api/attendance/abdul-kalam/[id]
   
   Security & Authorization Pipeline:
   Step 1: Authenticate user session via createServerSupabaseClient() and getUser().
           If invalid/absent -> HTTP 401 Unauthorized.
   Step 2: Fetch user profile and verify role:
           Allowed roles: STAFF_MENTOR, SUPER_ADMIN.
           If STUDENT, SEMI_ADMIN, PTF_SECRETARY -> HTTP 403 Forbidden.
   Step 3: Validate request payload:
           attendanceId: valid UUID.
           status: must be one of 'PRESENT', 'ABSENT', 'LATE', 'EXCUSED'.
           reason: mandatory string (minimum 3 characters).
   Step 4: Fetch authoritative attendance record from database:
           Verify record exists -> HTTP 404 ATTENDANCE_NOT_FOUND if absent.
           Verify status is actually different -> HTTP 400 NO_STATUS_CHANGE if identical.
   Step 5: Verify Abdul Kalam eligibility:
           Query public.special_class_eligibility for record.student_id.
           If not eligible -> HTTP 403 NOT_ELIGIBLE_FOR_SPECIAL_CLASS.
   Step 6: Enforce Ownership (Original Creator):
           If role === 'STAFF_MENTOR':
             Check user.id === record.mentor_id.
             If mismatch -> HTTP 403 ORIGINAL_CREATOR_ONLY.
   Step 7: Enforce 24-Hour Cutoff against Server Time:
           If role === 'STAFF_MENTOR':
             Check `serverNow.getTime() <= recordCreatedAt.getTime() + 24 * 60 * 60 * 1000`.
             If expired -> HTTP 409 ATTENDANCE_EDIT_WINDOW_EXPIRED.
   Step 8: Execute in-place update on public.attendance:
           Update `status`, `last_edited_by`, `edit_reason`, `updated_at`.
   Step 9: Insert immutable audit entry into public.attendance_audit_history.
   Step 10: Log institutional system audit event into public.audit_logs.
